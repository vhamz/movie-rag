# Workflow

## Цикл одной итерации

1. читаю задачи итерации в tasklist.md
2. пишу код / файлы только этой итерации
3. запускаю команду проверки из tasklist.md
4. если зеленая — обновляю статус в tasklist.md и коммичу
5. перехожу к следующей итерации

## До кода

- проверить, что предыдущая итерация закрыта (статус done, коммит есть)
- понять, какие файлы создаются/меняются, и не лезть в остальные

## Проверка

- каждая итерация проверяется своей командой из tasklist.md
- начиная с итерации 3 дополнительно гоняю uv run pytest tests/ -v
- если проверка падает — чиню в рамках той же итерации, не тащу дальше

## Когда обновлять tasklist

- сразу после успешной проверки итерации, тем же коммитом

## Коммиты

- один коммит на итерацию (мелкие фиксы можно отдельным)
- сообщение коротко о сути: "iter 3: chunking по абзацам с overlap"
- в коммит не попадают data/raw, data/processed, data/index

## Запрещено

- переходить дальше с красной проверкой
- менять файлы чужих итераций "заодно"
- коммитить сгенерированные данные и индекс
- добавлять зависимости без необходимости
